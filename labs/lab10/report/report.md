1. В Cisco Packet Tracer построена сеть, включающая маршрутизатор, коммутаторы, пользовательские ПК и серверы (web, file, mail, DNS).  

   ![Топология сети с серверами и клиентскими узлами](Screenshot_1.png){ #fig:007 width=80% }

2. На маршрутизаторе создан расширенный список контроля доступа `servers-out`, предназначенный для фильтрации трафика к серверам.  

   В соответствии с заданием настроены следующие правила:  
   - разрешён доступ к web-серверу по протоколу HTTP (TCP порт 80) для всех пользователей;  
   - для администратора дополнительно разрешены протоколы Telnet и FTP;  
   - для файлового сервера разрешён доступ по FTP с внешней сети и доступ к общим ресурсам из внутренней сети;  
   - для почтового сервера разрешены протоколы SMTP (порт 25) и POP3 (порт 110);  
   - для администратора также разрешены Telnet и FTP;  
   - для DNS-сервера разрешён доступ по UDP порту 53 из внутренней сети;  
   - разрешены ICMP-сообщения, направленные в сеть серверов.  

   ![Процесс настройки расширенного ACL на маршрутизаторе](Screenshot_2.png){ #fig:008 width=80% }

3. Дополнительно создан список доступа `other-in`, ограничивающий сеть Other.  

   В рамках настройки:  
   - запрещены любые обращения пользователей сети Other за пределы своей сети;  
   - разрешён доступ только для администратора;  
   - настроен список `management-out`, разрешающий доступ к сети управления только с административных узлов.  

4. Списки контроля доступа применены к соответствующим интерфейсам маршрутизатора в нужном направлении (in/out).

# Контрольные вопросы

1. Как задать действие правила для конкретного протокола?  
   Действие правила для конкретного протокола задаётся при создании записи в списке контроля доступа с указанием типа протокола (например, `tcp`, `udp`, `icmp` или `ip`) и действия `permit` или `deny`. Таким образом определяется, разрешён или запрещён трафик выбранного протокола.

2. Как задать действие правила сразу для нескольких портов?  
   Для задания правила сразу для нескольких портов используется ключевое слово `range`, которое позволяет указать диапазон портов (например, `range 20 21` для FTP). Также можно создавать несколько отдельных правил для разных портов.

3. Как узнать номер правила в списке прав доступа?  
   Номер правила можно узнать с помощью команды просмотра списков доступа, например `show access-lists`. В выводе каждая запись имеет свой порядковый номер (sequence number), который определяет порядок обработки правил.

4. Каким образом можно изменить порядок применения правил в списке контроля доступа?  
   Порядок правил можно изменить, задавая sequence number при добавлении новых записей или удаляя и добавляя правила заново в нужной последовательности. Также возможно редактирование списка с использованием нумерации, чтобы вставить правило в определённую позицию.
