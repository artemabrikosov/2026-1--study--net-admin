# Контрольные вопросы

1. В каких случаях следует использовать статическую маршрутизацию? Приведите примеры.  
   Статическую маршрутизацию следует использовать в тех случаях, когда структура сети достаточно проста, маршруты заранее известны и редко изменяются.  
   При статической маршрутизации администратор вручную указывает маршруты до нужных сетей, а маршрутизатор использует эти записи для пересылки пакетов.

   Статическая маршрутизация подходит для небольших сетей, где количество маршрутизаторов и подсетей ограничено.  
   Например, если в организации есть центральная сеть и один филиал, можно вручную прописать маршрут из центрального офиса к сети филиала и обратный маршрут из филиала к центральной сети.

   Также статическая маршрутизация используется для настройки маршрута по умолчанию.  
   Например, маршрутизатор локальной сети может иметь статический маршрут `0.0.0.0/0`, указывающий на маршрутизатор провайдера.  
   Такой маршрут применяется, если пакет направлен в сеть, для которой нет более точной записи в таблице маршрутизации.

   Еще один пример использования статической маршрутизации — резервные маршруты.  
   Администратор может создать дополнительный маршрут с увеличенной административной дистанцией, который будет использоваться только при отказе основного пути.

   В рамках выполненной работы статическая маршрутизация может применяться для связи между центральной сетью, сетью основной территории 42-го квартала в Москве и сетью филиала в г. Сочи.  
   Например, на центральном маршрутизаторе можно вручную указать маршруты к подсетям 10.129.0.0/24 и 10.130.0.0/24, а на маршрутизаторах удаленных площадок — маршруты обратно к сетям центральной части проекта.

2. Укажите основные принципы статической маршрутизации между VLANs.  
   Статическая маршрутизация между VLANs применяется тогда, когда разные VLAN являются отдельными IP-подсетями и для обмена данными между ними требуется устройство третьего уровня.  
   Обычно таким устройством выступает маршрутизатор или коммутатор третьего уровня.

   Основной принцип заключается в том, что каждая VLAN должна иметь собственную IP-подсеть.  
   Например, VLAN 101 может использовать сеть 10.128.3.0/24, VLAN 102 — сеть 10.128.4.0/24, а VLAN 103 — сеть 10.128.5.0/24.  
   Устройства внутри одной VLAN взаимодействуют напрямую на канальном уровне, а обмен между разными VLAN выполняется через маршрутизатор или L3-коммутатор.

   Для каждой VLAN должен быть настроен шлюз по умолчанию.  
   В роли шлюза обычно используется IP-адрес интерфейса маршрутизатора, подинтерфейса маршрутизатора или SVI-интерфейса на коммутаторе третьего уровня.  
   Все устройства внутри VLAN отправляют трафик в другие сети именно через этот шлюз.

   Если используется схема router-on-a-stick, один физический интерфейс маршрутизатора разделяется на несколько подинтерфейсов.  
   Каждый подинтерфейс соответствует отдельной VLAN, имеет собственный IP-адрес и использует инкапсуляцию 802.1Q.  
   Порт коммутатора, соединенный с маршрутизатором, при этом настраивается как trunk-порт, чтобы передавать трафик нескольких VLAN.

   Если используется коммутатор третьего уровня, для каждой VLAN создается SVI-интерфейс.  
   На этих интерфейсах задаются IP-адреса шлюзов, после чего включается маршрутизация между VLANs.  
   Такой способ обычно производительнее, чем router-on-a-stick, так как маршрутизация выполняется непосредственно на коммутаторе.

   При использовании статической маршрутизации важно вручную прописать маршруты до всех удаленных VLAN-сетей, которые находятся за другими маршрутизаторами.  
   Если маршрутизатор не знает путь к удаленной VLAN, он не сможет передать туда пакет.  
   Поэтому статические маршруты должны быть настроены в обе стороны: от отправителя к получателю и от получателя обратно к отправителю.
